# 🌾 농부의시장 배치도 도우미

뚝섬한강공원 · 양천파리공원 · 화랑대철도공원을 주마다 돌아가며 열리는 **농부의시장** 농가 부스 배치도를 만드는 도구입니다.

> **팀원은 [`농부의시장_배치도.html`](./농부의시장_배치도.html) 파일 하나만 받으면 됩니다.**
> 더블클릭하면 크롬/엣지에서 열리고, 설치도 인터넷도 필요 없습니다.

## 1. 팀원용 사용법 (5단계)

| 단계 | 할 일 |
|---|---|
| **0. 열기** | `농부의시장_배치도.html` 더블클릭 → 처음 화면에서 행사 일정(장소별 색 구분)을 누릅니다. |
| **① 참여 명단** | 「📥 엑셀 명단 넣기」로 명단 엑셀을 넣습니다. `장소` 열이 있으면 그 장소 농가만 골라 줍니다. 토·일(·금)별 체크로 참여를 정하고, 취소는 체크 해제, 추가는 「엑셀로 추가 명단 넣기」·「농가 직접 추가」. |
| **② 칸 만들기** | 격자를 클릭/드래그해 부스 칸을 만듭니다(한 칸 = 한 농가). 격자는 기본 **20줄×30칸(600칸)** 으로 넉넉하고, 오른쪽·아래 끝까지 칠하면 자동으로 늘어납니다(「＋5줄/5칸」 버튼, 최대 100×100). 위쪽 **「남은 칸 수」가 0이 되면** 참여 농가 수와 딱 맞습니다. **부스 앞면 방향(▲▼◀▶)** 은 자동으로 정해지고(통로 쪽), 틀린 줄은 「➜ 방향」 붓으로 방향을 고른 뒤 그 줄 부스 하나만 클릭하면 줄 전체가 바뀝니다. 장소 모양은 「기본형으로 저장」해 두면 다음 일정에서 불러옵니다. |
| **③ 농가 배치** | 「⚡ 자동 배치」→ 원재료·형태가 겹치는 농가를 붙지도, 마주 보지도 않게 최대한 멀리 놓습니다. 꼭 정해진 자리는 목록에서 농가 검색 → 클릭 → 칸 클릭하면 📌고정되고, 고정 농가는 자동 배치해도 안 움직입니다. 칸을 끌어 놓으면 자리 교체, Ctrl+Z로 되돌리기. |
| **④ 검수** | 손으로 바꾼 뒤 확인합니다. 가깝거나 **통로 건너 마주 보는** 유사 품목을 **선으로 잇고 원재료·형태마다 다른 색**으로 보여주며, 같은 원재료 농가끼리 가장 가까운 거리·평균 거리도 보여줍니다. 「🩹 문제 자리만 고치기」는 최소한만 옮겨 해결합니다. |
| **⑤ 저장·출력** | 색깔 배치도 **엑셀**(앞면은 굵은 테두리), 카톡용 **그림(PNG)**, **인쇄/PDF**. 배치가 끝나면 배치 화면의 「🎉 배치 완료 → 🖼 그림 저장」으로 바로 저장할 수도 있습니다. |

### 다른 팀원과 나누기
상단 **「💾 공유용 파일로 저장」** → 지금까지의 일정·명단·배치도가 **들어 있는** HTML 파일이 만들어집니다. 그 파일을 카톡·메일로 보내면 받은 사람은 더블클릭만으로 같은 화면에서 이어서 작업합니다.

- 작업은 브라우저에 자동 저장되지만 **그 컴퓨터에만** 남습니다. 중요한 작업 후에는 공유용 파일로 한 번 저장해 두세요(백업 겸용).
- 여러 사람이 **동시에** 고치면 마지막에 보낸 파일만 남습니다. 한 사람씩 차례로 넘겨 주세요.
- 받은 파일을 열 때 내 컴퓨터에 이전 작업이 있으면 어느 것을 열지 물어봅니다. 받은 파일을 열어도 이전 작업은 백업되어 「⚙ 설정 → 데이터 → 직전 백업으로 되돌리기」로 꺼낼 수 있습니다.

### 엑셀 명단 형식
첫 줄(머리글)에 아래 이름이 있으면 자동으로 알아봅니다. 순서·추가 열은 상관없고, 이름이 달라도 가져오기 창에서 열을 직접 고를 수 있습니다.

`연번 · 시도 · 시군구 · 농가명(필수) · 대표자 · 연락처 · 품목군 · 신청품목 · 신규여부 · 장소`

## 2. 비슷한 품목 판단과 자동 배치는 이렇게 동작합니다

### 2-1. 품목 분석 — 원재료 · 제품 형태 · 품목군
`신청품목`을 쉼표·괄호·공백으로 나눈 뒤(괄호 안 재료 포함), 두 사전(⚙ 설정에서 수정 가능)으로 태그를 붙입니다.

| 층 | 무엇을 보나 | 예 |
|---|---|---|
| **원재료** (가장 중요) | 결과물이 달라도 원재료가 같으면 같은 태그 (약 110가지) | `포도`·`포도즙`·`와인`·`뱅쇼`·`머루식초` → **포도** / `참깨`·`참기름`·`통깨` → **참깨** / `곰취떡`·`곰취만두`·`곤드레` → **산나물** / `침출차(작두콩,여주…)` → **작두콩·여주…** |
| 원재료 계열 | 원재료는 달라도 가까운 것 (약하게) | 블루베리↔아로니아 (베리), 참깨↔들깨 (깨), 굴비↔명태 (생선) |
| **제품 형태** | 원재료가 달라도 같은 형태면 손님이 겹침 | 즙·주스, 청·시럽, 잼·소스, 차, 식초, 술, 떡, 한과·강정, 부각, 김치, 장류, 젓갈·액젓, 기름 … |
| 품목군 | 엑셀의 품목군 (보조) | 가공식품류, 과실류 … |

- 오인 방지: `옥수수`≠`수수`, `김치`≠`김`, `고추장`≠`고추`, `명란`≠`계란`, `밤꿀`≠`밤`, `산마늘`≠`마늘`, `엿기름`≠`기름`, `로얄젤리`≠`젤리 간식` 등
- `쌀`·`소금`처럼 흔한 재료는 가중치를 절반으로 낮췄습니다.
- 명단 화면 위쪽 「🔁 겹치는 원재료」에서 이번 행사에 몇 곳이 같은 원재료를 쓰는지 바로 보입니다.
- 태그가 틀리면 농가 수정 창에서 원재료·형태를 직접 고치면 되고, 직접 고친 값은 사전이 바뀌어도 유지됩니다.

### 2-2. 유사도 × 거리(방향 포함) = 근접 위험도
```
유사도  s = 0.7 × 같은 원재료(흔한 재료 0.35)  [+0.1 × 더 겹치는 원재료]
          | 0.7 × 계열 가중치(0.1~0.7)          ← 같은 원재료가 없을 때
          + 0.35 × 같은 제품 형태 + 0.2 × 같은 품목군        (최대 1)

거리    p = 1 / 칸 수   (바로 옆 1 · 대각선 0.71 · 2칸 0.5 · 3칸 0.33 …, 6칸까지)
        부스 방향을 알면: 통로 건너 정면으로 마주봄 = 1 (바로 옆과 같음)
                          비껴서 마주봄 0.75 · 두 칸 비껴 0.4 · 등 맞댐 0.4배 · 같은 방향 앞뒤 줄 0.5배

근접 위험도 = s × p   →  위험 ≥ 0.45 · 주의 ≥ 0.3 · 참고 ≥ 0.15
```
| 상황 | 위험도 | 레벨 |
|---|---|---|
| 같은 원재료가 바로 옆 / 통로 건너 마주봄 | 0.7~1.0 | 🔴 위험 |
| 같은 원재료가 대각선 / 비껴서 마주봄 | 0.5~0.75 | 🔴 위험 |
| 같은 원재료가 2칸 거리 | 0.35 | 🟠 주의 |
| 같은 형태 + 같은 품목군이 바로 옆 (예: 떡집 두 곳) | 0.55 | 🔴 위험 |
| 같은 원재료가 3~4칸 거리 | 0.18~0.23 | 🟡 참고 |
| 같은 품목군만 바로 옆 | 0.2 | 🟡 참고 |

**부스 방향**은 칸을 그릴 때 자동으로 정해집니다. 한 줄로 이어진 부스는 줄과 수직인 두 방향만 후보로 두고, 앞이 비어 있는 쪽 중 통로 건너 다른 부스 줄이 있는 쪽을 앞면으로 고릅니다. 사방이 막힌 부스는 방향 없이 거리로만 판단합니다. 「마주보는 줄」 프리셋은 `↓줄 · 통로 · ↑줄 ↓줄(등 맞댐) · 통로 · ↑줄` 처럼 실제 장터 구조로 만듭니다.

배치 **등급(A~E)** 은 위험·주의 쌍의 수(농가 수 대비)로, **분산 점수**는 같은 농가를 무작위로 놓았을 때 대비 얼마나 덜 붙었는지로 매깁니다.

### 2-3. 자동 배치 알고리즘
"K개 칸에 N개 농가를 놓아 Σ 벌점(근접 위험도)을 최소화"하는 **이차 할당 문제(QAP, NP-hard)** 를 근사 해법으로 풉니다.
1. **탐욕 초기해**: 다른 농가와 겹치는 게 많은(배치가 어려운) 농가부터, 이미 놓인 농가와 충돌이 가장 적은 칸에 배치
2. **담금질 기법(Simulated Annealing)**: 임의의 두 칸 교환을 수십만 번 시도. 나빠지는 교환도 온도에 따라 확률적으로 받아들여 지역 최적해를 탈출. 교환 1회 비용은 두 칸의 이웃만 다시 계산
3. **마무리 최급강하** + **재시작 3회** 중 최선 선택 · 📌고정 칸은 제외
4. **레벨 가중 벌점** `G(x) = x + 4·max(0, x−0.3) + 8·max(0, x−0.45)`: 그냥 합을 줄이면 "먼 쌍 여럿을 조금 줄이는 대신 한 쌍을 붙여 버리는" 해가 나와서, 위험·주의 구간을 훨씬 무겁게 매겨 **붙거나 마주 보는 쌍부터 없애고, 남은 쌍은 최대한 멀리** 떨어뜨립니다.

「문제 자리만 고치기」는 같은 최적화에 **이동 1건당 벌점 1.0** 을 더해 필요한 만큼만 옮깁니다. 실제 명단에서 위험 2~5쌍을 2~6곳 이동으로 모두 해소했습니다.

**실제 전체 명단 120곳**으로 측정한 결과 (장소별 명단, 칸 수 = 농가 수, 방향 자동):

| 장소 (농가 수) | 칸 모양 | 무작위 배치 | 자동 배치 | 같은 원재료끼리 거리 (최소 / 평균) | 시간 |
|---|---|---|---|---|---|
| 뚝섬 (47) | 마주보는 2줄 | E, 위험 16·마주봄 5쌍 | **A, 위험 0·주의 0·마주봄 0** | 1 → **2.8칸** / 9.3 → **11.3칸** | 0.2초 |
| 뚝섬 (47) | ㅁ자 | D, 위험 7 | **A, 위험 0·주의 0** | 1 → **4.2칸** / 9.2 → 10.1칸 | 0.2초 |
| 화랑대 (42) | 마주보는 2줄 | E, 위험 12·마주봄 4쌍 | **A, 위험 0·주의 1·마주봄 0** | 1 → **2.8칸** / 7.3 → 9.9칸 | 0.2초 |
| 화랑대 (42) | ㅁ자 | E, 위험 10 | **A, 위험 0·주의 0** | 1 → **4칸** / 7.9 → 9.3칸 | 0.2초 |
| 양천 (31) | 마주보는 2줄 | D, 위험 4·마주봄 3쌍 | **A, 위험 0·주의 1·마주봄 0** | 1 → **2.8칸** / 5.6 → 7.7칸 | 0.2초 |
| 양천 (31) | ㅁ자 | D, 위험 4 | **A, 위험 0·주의 0** | 1 → **3.6칸** / 5.6 → 7.5칸 | 0.1초 |

## 3. 개발자용

```
farmers-market-layout/
├─ 농부의시장_배치도.html   ← 배포용 단일 파일 (빌드 결과, 팀원에게 이것만 전달)
├─ src/
│  ├─ index.html           ← 개발용 (여러 파일로 나뉜 원본)
│  ├─ css/app.css
│  ├─ js/dictionary.js     원재료 사전·제품 형태 사전
│  ├─ js/core.js           데이터 모델·기본 일정·부스 방향·저장/공유 파일
│  ├─ js/similarity.js     원재료/형태 분석·유사도·방향 근접도·검수
│  ├─ js/optimizer.js      자동 배치 (탐욕 + 담금질 + 최급강하)
│  ├─ js/excel.js          엑셀 읽기(SheetJS)·쓰기(ExcelJS)·PNG 그리기
│  ├─ js/layout-view.js    ②칸 만들기 ③배치 ④검수 화면
│  ├─ js/app.js            일정·명단·가져오기·저장출력·설정
│  └─ lib/                 xlsx 0.18.5 (Apache-2.0), exceljs 4.4.0 (MIT)
├─ tools/build.js          src → 단일 HTML (CSS/JS/라이브러리 인라인)
├─ tests/logic.test.js     핵심 로직 테스트
└─ sample/예시_참여명단.xlsx
```

```bash
npm run build   # 농부의시장_배치도.html 다시 만들기 (src 수정 후 꼭 실행)
npm test        # 원재료 추출·유사도·마주봄·방향·자동 배치·고정·이전 데이터 변환·공유 파일 테스트
```

- 프레임워크 없이 순수 JS(일반 `<script>`)라서 `file://` 로 더블클릭해도 동작합니다(ES 모듈·Web Worker는 file://에서 막히므로 사용하지 않음).
- 작업 데이터는 `localStorage` 에 자동 저장되고, 공유용 저장 시 `<script id="fm-embedded" type="application/json">` 자리에 JSON으로 들어갑니다.
- 실제 참여 명단(개인 연락처 포함)은 저장소에 올리지 않습니다. 예시 파일은 모두 가상의 이름·번호입니다.
